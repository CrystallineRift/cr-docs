# Game Audio

CR mixes through **Master Audio** (Dark Tonic), but nothing in CR calls it directly. Every sound
request goes through `IGameAudio`, and the vendor sits behind that one seam.

```
Assets/CR/Core/Audio/
  IGameAudio.cs              ← the whole audio surface CR uses
  MasterAudioBackend.cs      ← the real backend  (#if CR_MASTER_AUDIO)
  NullGameAudio.cs           ← the fallback, warns loudly
  UiSoundKeys.cs             ← shared menu sound names
  Logic/                     ← pure C#, no engine references, unit-tested
    AudioBus.cs
    AudioBusNames.cs
    MusicAction.cs / MusicChange.cs
    MusicTransitionResolver.cs
```

## Why the interface

Master Audio's API is entirely static — `MasterAudio.PlaySound3DAtVector3(...)`. Calling it from
`BattleHUD` or `BattleAbilityFxResponder` would weld a third-party package into the battle
presenters and make them impossible to construct in a headless EditMode test. Behind `IGameAudio`
the backend is swappable and the callers stay testable.

Keys are **backend-authored names** — Master Audio Sound Group and Playlist names — not asset paths,
so sound authoring stays inside the tool the designer is already using.

## Buses

`AudioBus` is an enum so a typo is a compile error and the settings UI can build its sliders from the
type:

| Bus | Carries |
|---|---|
| `Master` | Everything. The engine's global level, **not** a named bus |
| `Music` | Area playlists and battle themes |
| `Sfx` | Ability hits, creature cries, pickups — anything positional |
| `Ui` | Menu navigation and confirmation, kept separate so menus survive a muted world |
| `Ambience` | Looping room tone |

`AudioBusNames.ForBus()` maps the enum to the authored bus name and **throws** for `Master`, because
Master Audio has no bus by that name — returning `"Master"` would send the call to a bus that does
not exist and silently change nothing.

## Per-area music and ambience

`AreaAudio` is the audio counterpart to `AreaEnvironment`, and sits on the same area root:

| Field | Meaning |
|---|---|
| `musicKey` | Playlist for this area. Empty = inherit whatever is playing |
| `silenceMusicWhenUnset` | With no music key, stop the music instead of inheriting it |
| `ambienceKey` | Looping room tone. Empty = leave the current ambience alone |

Two areas are deliberately alive at once during a door transition — the arriving one loads and
initializes before the departing one unloads. Two consequences:

**`AreaAudio` has no `OnDisable` teardown.** A departing area stopping the music would cut off the
track the arriving area just started. Letting the arriving area overwrite the state makes the handoff
order irrelevant — the same problem `AreaEnvironment` solves with an owner check, solved here by not
needing one.

**Same track means keep playing.** `MusicTransitionResolver` compares the requested key against
what is already playing. Without that rule, walking between two areas that share a theme restarts
the track from the top every time the player crosses a door.

Playlist names are compared **ordinally** — they are asset identifiers, so `meadow_theme` and
`Meadow_Theme` are different tracks. This is covered by a test so it stays a decision rather than an
accident.

## Menu sound

`BattleHUD.OnPressed(button, soundKey, action)` wires a button to its action and its sound together.
It uses `clicked`, never `RegisterCallback<ClickEvent>` — a `Button` routes `NavigationSubmitEvent`
into `clicked` and never synthesises a `ClickEvent`, so a `ClickEvent` handler works for the mouse
and silently does nothing for gamepad A. See the changelog entry for 2026-08-05.

Sound names come from `UiSoundKeys` (`ui_confirm`, `ui_back`) rather than literals, so a screen
cannot invent its own spelling of "confirm" and end up silent — the backend drops an unmatched group
name without an error.

## Authoring

Two commands build the setup. Both are idempotent — re-running leaves existing work alone — and both
exist as commands rather than inspector clicks because this configuration lives *in scenes*: anything
hand-clicked is lost the next time Core is rebuilt, the areas are regenerated by
`cr_build_playtest_areas`, or Master Audio is reimported.

```bash
unity cmd --project-path . cr_setup_audio       # MasterAudio prefab, buses, starter Sound Groups
unity cmd --project-path . cr_wire_area_audio   # AreaAudio on Meadow and Cave, with ambience keys
```

Also on the menu as **CR → Audio → Set Up Master Audio** and **CR → Audio → Wire Area Audio**.

### What they create

| Sound Group | Bus | Variations | Source |
|---|---|---|---|
| `ui_confirm` | `Ui` | 3 | Fantasy Interface Sounds — `UI Tight 01–03` |
| `ui_back` | `Ui` | 2 | Fantasy Interface Sounds — `UI Tight 10–11` |
| `amb_cave` | `Ambience` | 1, looping | Endless Cave Ambience — `Cave Loop` |
| `amb_meadow` | `Ambience` | 3, looping | Dynamic Village Ambience — `Birds 01–03` |

Several clips per group on purpose: Master Audio picks a variation per play, which is what stops a
menu sounding like a machine gun under repeated presses.

Buses are created in `AudioBusNames` order. A group's `busIndex` is offset by
`MasterAudio.HardCodedBusOptions` (2), because Master Audio reserves the first slots for "no bus" and
"use master" — getting that offset wrong routes the group to the wrong bus silently rather than
erroring.

With no MasterAudio prefab in the scene, Master Audio logs its own warning and drops the call. That
is deliberately not swallowed — a silent drop is indistinguishable from working audio playing
nothing.

### Music is not authored yet

`AreaAudio.musicKey` is empty on both areas, which means *inherit*. The three imported packs are
ambience and interface sound; there is no music pack in the project, so naming a playlist would point
at nothing and be dropped without an error. Add a music pack first, then create a Playlist per track
and set `musicKey`.

### Unity 6 patches to vendor packages

**Two** imported packages fail to compile under Unity 6 for the same reason — `[SerializeField]`
applied where it is not a field declaration, which the compiler now rejects outright:

```
error CS0592: Attribute 'SerializeField' is not valid on this declaration type.
```

| File | What was wrong |
|---|---|
| `Plugins/DarkTonic/MasterAudio/Scripts/ResultObjects/PlaySoundResult.cs` | On a **class declaration** |
| `Plugins/CafofoStudio/Scripts/AmbienceMixer.cs` | On an **abstract property** |

Neither attribute did anything — a plain class is not a serialized field, and an abstract property
cannot be serialized — so both were removed, with a comment marking the patch. **Re-apply after
reimporting either package**, or the project will not compile.

## Not wired yet

These slots exist and are empty; they are content work, not code work:

- `AbilityConfig.useSfx` / `hitSfx` / `missSfx`
- `StatusConditionConfig.onApplySfx` / `onTickSfx` / `onRemoveSfx`
- `CreatureReaction.sounds[]` — creature cries, played by `CreatureBattlePresenter`
- Footsteps. Malbers already ships a surface system (`SurfaceEffects`, `SurfaceID`, `SurfaceTag`)
  with a demo scene, so this is clip assignment rather than a new system.

`FxLibraryScanner.ScanAudio` searches the VFX roots only
(`Assets/CR/Content/Effects`, `Assets/Vefects`, `Assets/VFX_Klaus`, `Assets/Piloto Studio`), so the
Ability Workbench's sound picker will not see clips imported anywhere else until an audio root is
added.
